# S2 重启恢复、并发、暂停与失败路径

状态：pending。任务类型：AFK。

需求：[PRD](../../../docs/prd/universal-onboarding.md)；技术方案：[开发设计](../../../docs/design/universal-onboarding.md)；交接：[进度](../../../docs/handoff/universal-onboarding/progress.md)。

## 目标与依赖

依赖 S1。将已跑通的接入闭环扩展为可靠的日常行为，包括重启、恢复、重复事件、并发窗口、网络故障和退出。

## 范围与模块线索

- 环境级认证协调、安装锁，以及 provider/数据源级持久暂停状态。
- 按环境、数据源、根会话及宿主实例管理所有权；PID 不作为唯一身份。
- `cmd/spawn.go`、`pkg/daemon/` 的上下文继承、最终同步和暂停竞争处理。
- `pkg/provider/` 已有根会话、子会话和能力开关逻辑。
- 旧实例检测；完整迁移和版本切换留给 S3。

## 验收标准

- [ ] 重启后复用有效凭据，恢复会话不重复追加或上传。
- [ ] 多窗口首次连接仅有一个授权流程，不反复弹浏览器。
- [ ] 重复事件与并发请求不创建重复 daemon，不跨环境共享断点。
- [ ] 同会话多宿主遵守单拥有者和 SESSION_BUSY 约定，非拥有者不能停止其会话。
- [ ] 暂停先持久化；新建会话、恢复、重启和与启动并发时都不会立即重新拉起。
- [ ] 401/403 与超时/网络错误分别处理，不把超时判为密钥失效。
- [ ] 正常退出、崩溃、授权取消与期限到达正确清理本任务产生的进程/锁。
- [ ] 子会话捕获沿用 provider 能力和后端 capability gating。
- [ ] 连续后台 Git 活动的可见窗口与前台焦点测试通过，不能仅检查是否存在 conhost.exe。

## 验证与边界

测试包含并发、失败恢复、暂停竞争和实际 Windows 子进程。沿用虚构会话与隔离目录；新测试完成后记录精确命令和结果。

暂停默认只作用于当前集成，不停止其他工具；不修改宿主进程或实现完整多拥有者租约。
