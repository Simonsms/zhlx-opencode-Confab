# S3 旧版迁移、配套升级与通用契约

状态：pending。任务类型：AFK。

需求：[PRD](../../../docs/prd/universal-onboarding.md)；技术方案：[开发设计](../../../docs/design/universal-onboarding.md)；交接：[进度](../../../docs/handoff/universal-onboarding/progress.md)。

## 目标与依赖

依赖 S2。用户能够从旧版迁移，升级失败能够回退；第二调用方无需 OpenCode SDK 就能使用同一核心协议。

## 范围与模块线索

- 识别受 Confab 管理的旧插件、钩子与进程；参考 `pkg/hookconfig/` 的备份与区块管理。
- 配套发行清单、不可变核心目录、协议版本兼容检查、受控切换。
- 托管更新与现有 `cmd/update.go` 的公网自动更新隔离。
- 选择一个现有非 OpenCode provider 做协议合同测试，不默认交付完整第二工具插件。

## 验收标准

- [ ] 先备份并停用旧自动启动入口，再停止旧进程和启用新入口，防止旧版重生。
- [ ] 不覆盖无法确认归属的自定义配置；新旧插件并存时不默默双跑。
- [ ] 升级不覆盖占用中的 EXE，失败时可以恢复原配套版本。
- [ ] 不同包内容具有不同发行身份，固定版本与摘要可追溯。
- [ ] 协议不兼容时拒绝接入，不回退到 PATH 中未知程序。
- [ ] 非 OpenCode 调用方完成 bootstrap/status/生命周期等适用协议合同测试，共用认证和协调逻辑。
- [ ] 用户与管理员有明确的迁移、升级、暂停、卸载及回退说明。

## 验证与边界

用隔离的“旧配置＋旧进程”夹具验证迁移，不直接拿用户实际配置做破坏性试验。必须覆盖 Windows 文件占用、半完成升级和回退后的凭据/状态可读性。

不增加独立常驻总服务，不为抽象复用重写全部 provider，不将全量第二工具用户体验扩入本切片。
