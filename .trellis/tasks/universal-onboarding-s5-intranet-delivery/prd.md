# S5 内网分发与部署验收

状态：pending。任务类型：HITL。

需求：[PRD](../../../docs/prd/universal-onboarding.md)；技术方案：[开发设计](../../../docs/design/universal-onboarding.md)；交接：[进度](../../../docs/handoff/universal-onboarding/progress.md)。

## 目标与依赖

依赖 S4 的通过结论，以及内网部署模式确认。沿用相同业务代码和协议，不 fork OpenCode。

## 待落实的部署条件

内网 npm/制品源是否存在、是否完全离线、目标后端、目标平台、私有 CA/代理要求和首次下发责任人目前均不能凭空补值。由用户/管理员在本阶段前提供。

## 范围与模块线索

组织环境预设、私服镜像或自包含目录包、完整依赖清单、安装升级回退文档，以及内网实测报告。

## 验收标准

- [ ] 有私服则从允许的内网源获取完整制品；完全离线则依赖和核心均已包含，不要求首次运行拉公网包。
- [ ] 不修改 OpenCode 源码或程序文件。
- [ ] 后端地址由预设提供，用户只添加插件或使用预置入口并完成首次授权。
- [ ] 外网凭据、会话状态和上传断点不被静默迁入内网。
- [ ] 禁止公网访问时仍能完成安装、授权、虚构会话同步和暂停。
- [ ] 私有证书/代理按实际环境配置，不以关闭 TLS 校验替代正确部署。
- [ ] 私服不可达、产物损坏、升级失败的状态明确且可回退。
- [ ] 内网首次接入、升级回退和运维交接均有实际验证证据。

本任务的产物形态由真实条件决定；不要在开发早期将“有内网私服”当成事实。
